# Timechain Continual-ARC learner

Single-model autonomous program learning with a Cypher Tempre Timechain,
Cambium auto-sprout, and explicit Chronosynaptic perspective notes. No subagents,
task solutions, task-specific policies, previous benchmark memory, or credentials
ship with the learner. Its default published model is
`deepseek/deepseek-v4.1-flash-1017`, reasoning effort `max`.

This is submission preparation, **not an organizer-verified result**. Earlier
interactive results from the development chat are a separate experiment and must
not seed any run of this package.

## Reproducible learner

Python 3.12 is required for the evaluation environment. Install this repository
with pip. The organizer imports `timechain_arc.learner:TimechainLearner` with no
constructor arguments and attaches it to its own isolated working directory and
tracking proxy. Real API credentials stay in the controller, outside the learner.

The generic skill is vendored at commit
`ad1afd50c89be5088df6b2ad73016d9950c54920`. Its unmodified sources and base
registries are hashed in `src/timechain_arc/vendor/PROVENANCE.json`. No experiential
chain or grown registry is imported from development. Each learner starts a new
chain with Cambium enabled. Primitive faculties generated by the skill are
distinct from the model-authored task programs.

Every action routes through the chain. Model decisions produce at least five
explicit alternative summaries and judgment scores, then a PoQ-gated seal.
Policy execution and observed feedback have separately labelled mechanical
receipts. Perspective scores and PoQ scores are model judgments, not calibrated
probabilities or independent experimental measurements.

The model may buy demonstrations, submit grids, act in games, and author Python
programs from the supplied observations. Grid programs are checked against every
retained paid demonstration. Generated programs run in bounded subprocesses with
a restricted import/builtin interface. These restrictions are defense in depth;
the official outer Linux/bubblewrap host provides the security boundary.

## Isolation and controls

Only width-1 schedules are supported. The official benchmark supports this
configuration for frozen tests. Each round has one instance.

Both task memory and Timechain mutations live in a working snapshot. `end_round`
verifies that the committed chain remains an exact prefix, then commits the memory
and chain together by switching snapshot directories. Incomplete working copies
are not used as learned state. A normal reference reset forgets all acquired
programs, notes, demonstrations, rings and grown faculties. It does not access
any other chain.

`tools/strict_host.py` extends the official `HostedLearner` controller: fresh
reference resets restart its process and remove its owned state/home directories.
Frozen resets use the official host's implementation unchanged: restart the
process and restore all writable files from the stream-end snapshot. Tests verify
that test-only information disappears and the stream-end rings match byte for
byte. The developer's Timechain and Robodojo are outside the sandbox.

The three-track matrix contains, per track:

* canonical seed-0 stream, followed by isolated seen and held-out tests;
* the identical stream with the learner freshly reset before every instance;
* fresh-reset controls on both test schedules;
* the official bare-model floor on both test schedules, at the same model/effort.

All model calls pass through the official accounting proxy. Model, provider route,
budget, usage, failed calls and software identities must remain disclosed. The
official checker must pass before any public result is presented as a submission.

## Run preparation

Install the pinned benchmark and its baseline controller in a separate Linux
environment. The controller revision is
`7a21baaaed2f964f1deea13ea29906b949af0959`; the learner depends on its public
benchmark package. If installing baseline sources from that checkout, install
them without dependency resolution after installing the same checkout's benchmark,
then install `httpx` and `agent-client-protocol==0.12.1`. The upstream baseline
package otherwise selects its tagged benchmark dependency.

Set `CONTINUAL_ARC_DATA` to a controller-owned dataset directory and fetch/check
the official pinned data. Do not expose it to the learner sandbox.

```bash
python -m unittest discover -s tests -v
python tools/matrix.py prepare --root /absolute/new-run-directory
```

The prepare command freezes source hashes and creates all 21 canonical stages.
Never reuse a preparation directory after changing the source. Running a paid
OpenRouter matrix additionally requires an explicitly authorized spending cap,
conservative endpoint price bounds and a pinned eligible provider:

```bash
python tools/matrix.py run --root /absolute/new-run-directory \
  --profile openrouter --spend-cap AUTHORIZED_USD \
  --prices /absolute/prices.json --pin-provider APPROVED_ENDPOINT
```

Configure `OPENROUTER_API_KEY` securely in the controller environment. It is never
forwarded into the learner. The same spend ledger covers the matrix's stages.
Do not claim all stages completed until their complete records have been checked.

## Subscription development route

`tools/go_bridge.py` is an optional **public-development-only** transport adapter
for the user's OpenCode Go subscription. It maps the canonical checkpoint to
`deepseek-v4.1-flash`, forwards `max` effort, identifies this client honestly, and
uses a stable reset-specific session ID. Provider usage receipts are retained
alongside official proxy accounting. The current provider catalog identifies this
alias as the October 17 checkpoint. It stops on quota/authentication rejection or
a response not reported as included Go usage, without a model fallback. It does
not enable extra usage or alter account settings.

Do not treat this adapter as organizer verification or assert that it independently
certifies the provider's retention policy. OpenCode publishes a zero-retention,
no-training agreement for standard DeepSeek through November 30, 2026; that policy
must be rechecked before future runs. Muse Contributor is not eligible for private
verification because it permits training on submitted content.

The official private run uses the organizers' OpenRouter account, tracking proxy
and sandbox, funded through their separate verification invoice. A Go subscription
does not pay that invoice. The public-development route does not replace that
required verification step.
